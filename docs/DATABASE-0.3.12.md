# 0.3.12 数据库修复、容量与验证

版本0.3.12 / 20，Room v6，备份格式v3。本版正式发布。验证边界：新增Room设备测试已编译，尚未执行；没有完成物理断电或首次多年原始明细升级验收。

## 修复内容

原`daily_usage`是可淘汰缓存，外部备份不包含长期日汇总，详细记录也没有90天到期策略。本版新增：

- `history_days`：独立长期日汇总，按时区、日期、指标、应用键、证据等级组成联合主键，不按年龄或容量淘汰。
- `history_seals`：每个完整日期、指标的行数、内容摘要和LOCAL/IMPORTED来源。写入先替换整个桶，重试不重复累加。
- `retention_state`：已提交的本机清理边界。删除与边界在同一事务提交或回滚。
- v5→v6仅新增表和索引，注册v1至v6完整升级路径；不使用破坏性重建。

保留边界按原记录时区的民用日期计算，保留至少90个完整日期及今天的明细，适配23/25小时DST日期。先持久化长期汇总，再重新验证待清理日期的双指标、摘要、待重放状态、未闭合及跨边界区间、精确边界检查点。

条件不足时停止清理并保留额外明细；不会为满足90天上限强制删除。仅清理非LEGACY_IMPORT原始事件和algorithm=2本机区间；旧格式历史和无法安全替代的外部导入明细继续保留。已压缩日期不允许用局部片段覆盖；近期重算从保留的检查点恢复。

日/月报表可以使用长期汇总。旧小时、任意部分日期或跨时区精确重分桶需要原始明细；缺少明细时明确提示限制，不把缺失伪装成零。

近期区间使用`metric,end,start`索引，较早日期使用`metric,start`索引，两者保持半开区间重叠语义和按start返回结果。

## 备份与恢复

备份v3增加长期日汇总与完整性标记，继续支持v1/v2导入。导入使用事务内SQLite临时表，完整读到gzip尾部并校验后逐桶合并；坏摘要、缺指标、重复键、缺标记、截断压缩或额外内容会整体回滚。

重复恢复按完整桶处理，不相加；已有本机桶优先，有本机明细时使用本机计算规则。外部汇总标记为IMPORTED，读取时不提升为本机已确认用时。外部采集状态和清理边界不激活。

已有本机压缩边界之前的局部明细无法无歧义合并，导入会回滚并保留本机历史，提示在独立安装中恢复。v3备份不应交给只支持旧格式的应用；Room v6数据库也不支持直接降级到v5。

升级前请在现有应用中导出备份。发布安装包使用开发签名；遇到签名冲突应保留原安装并核对签名，避免卸载导致本机数据丢失。

## 复现与剩余限制

```sh
python tools/verify_dual_storage.py
python tools/audit_history_storage.py
```

十年审计在`.qa-temp`中生成独立UUID目录；可能占用较多磁盘空间。测试脚本不连接个人数据库。Android测试需专用隔离安装或模拟器。

发布前仍需设备上的Room升级/恢复与物理断电验证；首次多年原始明细回填可能较慢，设备后台时间预算和接近满盘场景尚未完成验收。时区变化、缺锚点、待算或未闭合数据会推迟清理。长期历史按原时区日总量保存，尚无多设备汇总冲突选择或历史时区切换界面。
