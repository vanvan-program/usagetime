# 0.3.11 双指标统计修复与验证

主要使用时间与屏幕可见时间分别计算；屏幕可见按应用累计，应用之间允许重叠。本次修复不以 vivo 或其他厂商系统统计为正确性标准。

## 修复及复现

以下回放使用合成事件时间，时间单位为毫秒。测试源码见 `AuditReplayTest`、`ProofIntegrityTest`、`PendingClosuresTest`。

| 问题 | 最小复现与旧行为 | 修复 |
|---|---|---|
| F01 明确失焦后回退 | 自有窗口 10 RESUME/FOCUS_GAIN，30 FOCUS_LOSS，70 STOP；原来后 40ms 仍为主要候选 | 持久保留否定焦点证据，失焦后主要归属未知 |
| F02 无关窗口闭合误确认 | one 在 0 获得焦点，two 在 10 获得焦点、20 失焦停止；原来 two 闭合能确认 one 的前段 | 审计引用与 proofRefs 分离，闭合必须对应实际证明及实例 |
| F03 旧进程状态复活 | 旧实例开始后缺失结束；新进程 40 开始、60 结束；原来 60 后旧实例恢复归属 | OWN_SESSION_START 退役旧自有节点，不猜旧进程结束时刻 |
| F04 调时跳变被计为用时 | 检测时钟异常后仍出现 RESUME/STOP；原来后续墙上时间差仍可进入累计 | 成对采样带不确定度，隔离不可信时钟域直到新锚点 |
| F05 缺失闭合伪造覆盖 | 10 RESUME 后一直没有结束，后续查询无新事件；原来主要 unknown 可为零 | 开放尾段保留未知，不把持续使用假设作为可靠累计 |
| F06 无实例重复 RESUME | 同包同类 instance=null，0/10 RESUME，20 PAUSE；原来只告警仍继续归属 | 无身份碰撞传播 UNKNOWN；精确 id 重复仍幂等 |
| F07 分段先写获胜 | 自有焦点和公开生命周期混合闭合；原来完整 UNKNOWN、分段 INFERRED | 精确 proof 匹配与时间界限，允许冲突保守降级已终结行 |
| F08 默认隐藏未知 | 关闭“显示确定时间”时质量说明一起隐藏 | 质量说明常驻；CSV、小时/日/月汇总口径同步 |

## 升级行为

证据算法版本为 `strict-evidence-0311`，数据库结构版本仍为 5。保留原始事件，重新生成派生区间与缓存。旧自有焦点事件缺少所需单调时钟元数据时不重新确认为可靠焦点证据。

本版累计可能比旧版减少：失焦、未闭合、实例歧义及不能定位的调时区间转为显式未知。未知不等于零使用；候选估计与未知覆盖可能重叠，不能简单相加。

## 验证结果

- 核心 JUnit：155 项通过，含 17 项合成事件审查回放；应用 JVM：25 项通过。
- SQLite：24 项检查通过。
- 完整重放与分段入库：200 组切点矩阵通过，逐时间单位比较归属、未知和暂定状态。
- Preview 构建、Lint 与 Android 仪器测试源码编译通过。
- F08 以源码检查和编译验证；本次没有执行界面截图或设备端交互验收。

回放基线 138 项与审查回放 17 项合计为上述 155 项核心测试，不能重复相加。

## 尚未验证的设备行为

本次没有执行设备端仪器测试，分屏、画中画、重启、锁屏和真实系统调时只覆盖合成事件回放。厂商事件序列差异以及真实缺失事件的发生方式没有由这些测试证明。

公开 UsageEvents 不能提供完整的第三方焦点、真实遮挡或丢失事件结束时刻。生命周期可见候选不等于已证明真实可见，不把时间显示到毫秒视为实际准确度保证。

## 重放

运行 `build-local.ps1` 可编译并直接执行核心与应用 JVM 测试；运行 `python tools/verify_dual_storage.py` 可检查 SQLite 迁移与一致性。Android 仪器测试需要独立测试环境，不应针对个人日常数据库执行。
